- Tipo: feature.

- Feature: feature-home-image-links-01.
- Aprobación explícita en esta conversación: usuario confirmó que no se toque nada fuera de Editar inicio, aprobó los criterios de URL HTTPS directa, previsualización y fallback, y pidió «aplícalo».
- Objetivo: permitir usar enlaces directos de imágenes además de archivos en cada módulo de Editar inicio con control de fotos.
- Alcance: control compartido de medios usado por Presentación y cards de Categorías, Productos destacados y Recién llegados. Admitir URL HTTPS directa para la foto principal y agregar un enlace por guardado al carrusel; los archivos actuales siguen disponibles y las galerías conservan el límite de seis.
- Fuera de alcance: otras páginas y módulos, POS, catálogo, inventario/fotos del producto, cambios de negocio o navegación, dependencias, migraciones, scraping, descarga remota al servidor o proxy. Solo el navegador carga las URL.
- Persistencia: reutilizar `HomePage.content.hero_image_url`, `HomeCard.image_url` y `gallery` ya existentes; las galerías podrán contener paths locales o enlaces HTTPS. No reutilizar `link_url`, que sigue siendo destino de la card.
- Criterios de aceptación: 1) En Presentación y cada sección de cards se puede subir archivo o introducir enlace directo HTTPS para la portada, conservando las acciones actuales de quitar. 2) Se puede añadir un enlace HTTPS al carrusel, conservando la subida múltiple y máximo de seis imágenes. 3) La previsualización se carga en navegador; una URL inválida o que falla muestra mensaje y bloquea el guardado de esa fuente, manteniendo la imagen persistida y sin tocar datos si la validación falla. 4) Rechazar HTTP, esquema ejecutable, URL malformada, host ausente, credenciales y direcciones localhost/IP privada literal; no hacer solicitudes desde servidor. 5) Guardar enlaces como URLs, mostrarlos correctamente en home/carruseles y nunca tratarlos como rutas para borrar archivos. 6) Una URL de card no se copia a la foto del producto ni cambia inventario; conservar sin cambios el comportamiento existente de archivos.
- Archivos en alcance: `resources/views/admin/partials/media-upload.blade.php`; `resources/views/admin/home/edit.blade.php`; `resources/views/admin/home/partials/card-form.blade.php`; `resources/js/home-editor.js`; `app/Http/Requests/Admin/HttpsImageUrl.php`; `app/Http/Requests/Admin/HomeContentRequest.php`; `app/Http/Requests/Admin/HomeCardRequest.php`; `app/Http/Controllers/Admin/HomeContentController.php`; `app/Http/Controllers/Admin/HomeCardController.php`; `app/Models/HomePage.php`; `app/Models/HomeCard.php`; `app/Services/GalleryService.php`; `tests/Feature/AdminHomeContentTest.php`; `tests/Feature/HomeCardTest.php`.
- Paso 1: agregar entradas URL accesibles y ayudas que expliquen enlace directo, preview y dependencia del host externo; mantener intactos los inputs de archivo y borrado.
- Paso 2: validar fuente URL solo en HTTPS, límite de longitud y host seguro; rechazar envío simultáneo de archivo y URL o de quitar y reemplazar. Extender validación de galerías y conservar el máximo actual.
- Paso 3: persistir URL principal en campos existentes y URL adicional en gallery. Limpiar/retirar archivos locales solo tras guardar correctamente; excluir URL de operaciones de Storage y resolver URLs externas sin `Storage::url`.
- Paso 4: previsualizar URL en el navegador, informar carga/error y bloquear un enlace nuevo hasta que cargue; ante error dejar visible/restaurar la imagen que ya estaba guardada. No enviar solicitudes de imágenes desde backend.
- Paso 5: añadir cobertura de persistencia y validación de hero/cards, preservación ante fallo y no propagación de URL al inventario; inspeccionar el diff limitado a los archivos enumerados. No ejecutar Testing sin solicitud explícita.
- Plan de rollback: restaurar el parcial, JS, requests y controladores a carga por archivo; no eliminar columnas, filas, URLs ni archivos. Si ya hay URLs guardadas en `gallery`, conservar los guardas de resolución y borrado seguro hasta exportar o convertirlas; revertir esos guardas solo tras confirmar que no quedan enlaces persistidos. No restaurar base de datos completa ni tocar inventario.
- Riesgos/limitaciones: el navegador del visitante contacta al host enlazado, y HTTPS no garantiza disponibilidad ni que el host entregue una imagen; explicar que debe pegarse la dirección directa de la imagen, no la página de resultados de Google. La verificación de carga ocurre en navegador, sin garantizar disponibilidad futura.

Memory MCP no expone recursos ni `search_nodes/open_nodes`; se usa respaldo `.memory/`. Shell Bash, read/glob/grep y patch disponibles; `git status` mostró muchos cambios ajenos/preexistentes, que quedan fuera de alcance.
