- Tipo: feature
- Aprobación explícita de este plan en herramienta de preguntas: usuario seleccionó «Aplicar y probar aislado». Autoriza feature y pruebas simuladas/BD en memoria, no guardar ubicación real.
- Feature: feature-home-mapa-enlace-corto-01.
- Objetivo: aceptar enlace corto de Google Maps en el campo del mapa, convertirlo al guardar y mostrar mapa dentro de la home sin API de pago ni cambios de datos reales durante implementación.
- UX mínima: conservar selector de tipo de mapa; con Google seleccionado, el campo de URL acepta enlace corto o URL de inserción ya admitida. Actualizar etiqueta/ayuda para explicar esto. El enlace Cómo llegar sigue independiente, no sobrescribirlo ni modificar el modo pin automáticamente. No añadir JS, búsqueda de direcciones ni geocodificación arbitraria.
- Paso 1: crear app/Services/GoogleMapsLinkResolver.php mediante Artisan para resolver solamente enlaces HTTPS maps.app.goo.gl admitidos. Reutilizar validación existente de URLs Google como base, sin credenciales/puertos/hosts arbitrarios. Resolver redirecciones manualmente, sin seguimiento automático, validar cada destino antes de pedirlo, limitar saltos/longitud y tiempos de conexión/respuesta y presupuesto total.
- Paso 2: extraer el punto real de URL final Google Maps usando coordenadas de lugar !3d/!4d o query estructurada de coordenadas válida. Validar rangos latitud/longitud y exigir origen Google Maps; no inferir punto desde token corto, nombre de negocio ni @centro de cámara. Si no se puede resolver inequívocamente, error claro sin guardar.
- Paso 3: obtener URL canónica de inserción mediante petición acotada a https://maps.google.com/maps con q de coordenadas validadas y output=embed; aceptar solo redirección final HTTPS Google /maps/embed?pb=... que HomePage.isGoogleMapsUrl(..., true) ya permite. No ampliar whitelist de iframes ni guardar el enlace corto como src. El diagnóstico del enlace real confirma este recorrido y respuesta 200 del embed resultante.
- Paso 4: HomeContentRequest acepta como candidato de map_embed_url solo los embeds existentes o el formato corto validado sin llamadas de red. HomeContentController.update, después de autorización/validación y antes de adquirir bloqueos/escribir/gestionar imágenes, resuelve el candidato corto del bloque location y usa ese valor canónico en el payload validado. No hacer red dentro de prepareForValidation ni durante render público ni bajo transacción.
- Paso 5: falla de red, bucle, enlace no resoluble o destino no autorizado -> ValidationException en content.map_embed_url, sin modificar contenido/ubicación previa. Conservar link original en entrada antigua para reintentar; conservar Google embed manual y modo pin actuales. Maps_url de navegación, fotos, precios, categorías y datos físicos intactos.
- Paso 6: actualizar resources/views/admin/home/partials/location.blade.php (tipo Google y ayuda/etiqueta de URL). No cambiar layout público, HomePage.mapEmbedUrl ni el contrato estricto de iframe; ya renderizan la URL canónica.
- Paso 7: pruebas con Http::fake y prevención de conexiones no simuladas, en tests/Feature/AdminHomeContentTest.php o prueba dedicada si resulta necesaria. Cubrir enlace real como fixture de redirecciones, punto correcto y src persistido/renderizado; embeds previos y pin; 404/timeout/no coordenadas; redirecciones a host no Google/HTTP/IP privada/puerto/credenciales; bucles/límite; permiso de empleado; fallo preserva ubicación anterior y no escribe. No contactar Google ni datos reales durante Testing.
- Archivos previstos: app/Services/GoogleMapsLinkResolver.php (nuevo, directorio existente); app/Http/Requests/Admin/HomeContentRequest.php; app/Http/Controllers/Admin/HomeContentController.php; resources/views/admin/home/partials/location.blade.php; tests/Feature/AdminHomeContentTest.php y/o prueba dedicada según cobertura. HomePage.php y home.blade.php: inspección sin cambios previstos.
- Criterios de aceptación: Google seleccionado + enlace corto del usuario en mapa -> al guardar queda URL Google embed con punto real, home genera iframe válido; no se inserta maps.app.goo.gl directamente; errores visibles sin borrar configuración anterior; sin red durante visitas públicas; no variar Cómo llegar/pin ni otros apartados.
- Plan de rollback: revertir exclusivamente esta feature respetando fixes previos; no hay esquema/migración ni datos reales escritos durante implementación. URLs canónicas ya guardadas por el usuario siguen siendo embeds admitidos por versión anterior, así que no se eliminan. Respaldar ubicación previa antes de cambiarla en uso real; restaurarla explícitamente si el usuario lo solicita, sin restaurar toda BD ni tocar ventas/fotos.
- Riesgos y límites: Google puede cambiar redirecciones o bloquear conectividad; nunca prometer resolver rutas, áreas o enlaces sin punto inequívoco. Presupuesto de red acotado y fracaso seguro; no usar cookies/login ni APIs privadas. Prueba HTTP 200 no sustituye prueba manual de iframe en navegador.
- Exclusiones: API keys/facturación, nuevas dependencias, esquemas, geocodificador general, iframe HTML libre, dominios arbitrarios, cambiar ubicación real automáticamente, cambios JS/CSS/builds o historial git.
- Testing: solo con solicitud explícita; ofrecer aplicar y probar aislado. Si se autoriza, forzar SQLite :memory:, configuración no cacheada, Http::fake y almacenamiento falso donde corresponda; no usar enlace externo real en suites. Verificación básica: php -l, Pint y diff.
- Skills pertinentes ya cargadas: ponytail, laravel-best-practices, testing-best-practices y tailwindcss-development si se modifican clases (sin cambios de estilo previstos). Herramientas memoria MCP no disponibles, fallback .memory/; lectura/edición/PowerShell/webfetch disponibles. .ai/rules no existe según inspección.

- Estado: IMPLEMENTADO.
- Cambios aplicados: GoogleMapsLinkResolver resuelve hasta 3 saltos con allow_redirects=false, URL/hosts HTTPS existentes validados antes de pedirlos y tras cada Location, máximo 8192 caracteres y presupuesto total de 8 s con conexión <=2 s/petición <=3 s. Extrae un único punto de lugar !3d/!4d o query de coordenadas anclada y en rangos, sin usar @cámara ni rutas. Obtiene Google /maps/embed?pb= canónico sin ampliar whitelist de iframe. Red solo después de autorización/validación, antes de transacción y únicamente al guardar el bloque location con candidato corto.
- Detalle comprobado y corregido: Google devuelve 404 a HEAD en la ruta maps.google.com de conversión, pero GET devuelve 301 al embed. Se informó antes de ajustar; origen corto sigue HEAD y conversión usa GET con stream=true sin descargar cuerpo deliberadamente. Diagnóstico externo de solo lectura confirma HEAD corto 302, GET conversión 301 y embed 200; no se guardaron datos reales.
- Integración: HomeContentRequest permite candidato corto solo en location; guardado completo legacy no puede persistir corto sin resolver. HomeContentController usa contenido preparado con src canónico; fallo produce error de campo y preserva todo. UI de Ubicación explica tipo Google y campo de enlace corto o inserción. Cómo llegar y modo pin se conservan.

HomePage/home pública, fotos, inventario, JS/CSS y dependencias intactos.
