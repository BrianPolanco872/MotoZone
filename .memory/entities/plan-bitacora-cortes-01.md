- Tipo: feature
- Objetivo: Crear una Bitácora de solo consulta para buscar cortes guardados por fecha y empleado o por el corte global, verlos paginados de 8 en 8 y exportar los resultados filtrados en un PDF consolidado.
- Alcance y decisiones: Módulo/pantalla independiente y de solo lectura, conservando intacto el historial actual; fecha exacta opcional; selector por defecto «Todos (global)» que consulta snapshots globales, o empleado que consulta sus snapshots; el PDF consolidado comprende todos los resultados filtrados, sin limitarse a la página web actual; mostrar los snapshots almacenados sin recalcularlos.
- Pasos: (1) Crear BitacoraController con listado y exportación PDF y una consulta compartida validada por fecha/scope/empleado, con relaciones eager-loaded y orden estable por fecha, versión e ID. (2) Obtener las opciones de empleados/admin incluyendo cuentas inactivas y soft-deleted para preservar la consulta histórica. (3) Añadir rutas GET bajo el grupo existente de acceso POS y permiso pos.cut.manage; no crear permiso nuevo. (4) Añadir enlace Bitácora a la navegación de usuarios autorizados. (5) Crear pantalla con calendario, selector global/empleado, botón Filtrar, tabla de solo lectura, estado vacío, exportación PDF y paginador de 8 con filtros conservados. (6) Crear plantilla PDF consolidada multipágina en carta horizontal con filtros, fecha de generación y tabla estructurada; reutilizar barryvdh/laravel-dompdf instalado y no sumar versiones financieras entre sí. (7) Agregar pruebas feature de autorización, filtros de fecha/scope/empleado, paginación, contenido/cabeceras PDF y comportamiento de solo lectura.
- Archivos afectados: app/Http/Controllers/Pos/BitacoraController.php (nuevo: listado, consulta compartida y PDF); routes/web.php (rutas GET); resources/views/layouts/admin.blade.php (enlace de navegación); resources/views/pos/bitacora/index.blade.php (filtros, resultados y paginador); resources/views/pos/bitacora/pdf.blade.php (reporte consolidado); tests/Feature/PosBitacoraTest.php (nuevo: permisos, filtros, paginación, PDF y solo lectura).
- Criterios de aceptación: (1) Usuarios autorizados acceden; sin permiso se bloquea el acceso. (2) El calendario filtra una fecha exacta y el selector permite empleado o global. (3) La opción global consulta solo DailyCut::SCOPE_GLOBAL; la individual filtra DailyCut::SCOPE_EMPLOYEE por user_id. (4) Los resultados se ordenan de forma estable y se muestran 8 por página manteniendo query string. (5) El PDF application/pdf incluye todos los registros del filtro aunque estén en otras páginas web, metadatos del filtro, empleado/global y versión. (6) Solo lectura: no hay rutas/acciones para editar o eliminar cortes. (7) Las pruebas cubren autorización, diferencias de scope, fecha, empleado, octavo/noveno registro y exportación completa.
- Plan de rollback: Retirar las rutas GET, el nuevo controller, las dos vistas, el enlace de navegación y la prueba nueva. No hay migración, cambio de datos ni dependencia nueva.
- Riesgos: El PDF sin filtro de fecha puede crecer con el historial y consumir tiempo/memoria; los snapshots pueden tener varias versiones de un mismo día y no deben sumarse como si fueran cortes independientes; si no existe snapshot global para una fecha, la Bitácora no lo sintetiza sumando cortes individuales. El permiso pos.cut.manage limita la consulta de cualquier empleado/global a usuarios ya autorizados. El bug histórico bug-corte-reabrir-dia-01 consta como implementado por fix-corte-reabrir-dia-01; el plan evita tocar ese flujo.
- Dependencias externas: Ninguna nueva. barryvdh/laravel-dompdf v3.1.2 ya está instalada.
- Alternativas consideradas: Reutilizar o renombrar la vista historial existente reduce archivos, pero se descarta porque esa pantalla es global-only y contiene eliminación de cortes; una Bitácora independiente respeta «otro módulo» y permite que sea de solo lectura sin cambiar el historial actual. Recalcular cortes con DailyCutService se descarta para no alterar snapshots históricos; se consulta DailyCut.totals persistido.
- Validación técnica: codesearch_* no está disponible; la superficie se mapeó con búsqueda/lectura local. .ai/rules/index.md no existe en este workspace.
- Estado: IMPLEMENTADO
- Cambios aplicados: Se creó el módulo Bitácora de solo lectura con filtros de fecha y empleado/global, snapshots globales o individuales, paginación de 8, navegación autorizada y PDF consolidado multipágina con todos los registros filtrados. Se añadieron pruebas feature para permisos, filtros, paginación y exportación completa.
- Desviaciones del plan original: No hubo desviaciones funcionales. No se ejecutaron las pruebas; el intento de Pint para Blade no pudo correr porque faltan prettier y sus plugins, que no se instalaron.
