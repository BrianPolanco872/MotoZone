- Tipo: feature
- Feature: feature-home-cards-promocionales.
- Objetivo: refactorizar por completo el editor "Editar inicio" a tarjetas promocionales independientes con carga de medios limpia (preview inmediata), sin depender del inventario ni del POS.
- Aprobación explícita: pendiente de confirmar dos decisiones de alcance (publicaciones actuales y modelo de precio). Sin aprobación no se implementa.
- Sustituye parcialmente a: plan-categorias-fotos-carrusel-01 (se conservan sus fotos/carrusel y se reutiliza GalleryService y x-carousel).
- Decisiones del usuario en este mensaje (última instrucción prevalece): precios manuales (regular y oferta) en las cards de producto; etiqueta/badge libre; categorías promocionales creadas a mano en la home, independientes del POS; reordenamiento simple y funcional; dark mode elegante con acento naranja; JS nativo o Alpine, sin dependencias pesadas.
- Decisiones técnicas propuestas: una sola tabla `home_cards` con `section` (categories|products|new) y campos tipados; la presentación (hero) permanece en `home_pages` (ya tiene foto principal + galería); se reutilizan `GalleryService` y `x-carousel`; JS nativo con FileReader y botones Subir/Bajar/Eliminar (sin librerías); se eliminan la selección y búsqueda del catálogo del editor y sus rutas/requests/tests.
- Fuera de alcance: precios/existencias desde inventario, enlaces obligatorios a producto, bloques de cabecera/pie, editor visual drag-and-drop con librerías, cambios en el POS o en el catálogo, commits.
- Esquema propuesto `home_cards`: id; section string(20) index; sort_order unsigned int default 0 index; is_active boolean default true; title string(160); subtitle string(255) nullable; description text nullable; image_path string nullable; gallery json nullable; price decimal(12,2) nullable; sale_price decimal(12,2) nullable; badge string(60) nullable; link_url string(2048) nullable; link_label string(80) nullable; timestamps.
- Migración de datos: al crear `home_cards`, copiar una sola vez la selección actual (categorías home_visible, productos home_visible activos y new_product_ids) como cards activas para que la portada no quede vacía; no se borran datos existentes.
- Pasos: 1) migración `home_cards` + backfill; 2) modelo HomeCard con scopes, portada/galería y descuento; 3) HomeCardRequest con límites de 6 fotos, 20 MB, 6000×6000, precio/oferta coherentes y enlace opcional; 4) HomeCardController store/update/destroy/move con transacción y borrado after-commit; 5) rutas admin nuevas y retirada de las rutas de selección; 6) editor dark con secciones y cards, dropzone + FileReader y miniaturas con X; 7) home pública leyendo cards para categorías/productos/recién llegados; 8) simplificar HomeContentController a presentación (y publicaciones si se conservan); 9) tests de CRUD, orden, fotos, visibilidad y render; 10) Pint, Blade y rutas.
- Límites: 6 fotos por card (portada incluida), JPEG/PNG/WebP 20480 KB y 6000×6000; el límite real del servidor web se comunica, no se promete. Precio máximo 99,999,999.99 y oferta ≤ precio.
- Plan de rollback: exportar `home_cards` y las tablas editoriales antes de migrar; la migración es aditiva; conservar `home_pages`, `home_publications` y las fotos en disco; revertir vistas/controladores restaura la selección previa; no borrar imágenes ni restaurar la BD completa sobre ventas nuevas.
- Archivos previstos: database/migrations/2026_11_11_120000_create_home_cards_table.php; app/Models/HomeCard.php; app/Http/Requests/Admin/HomeCardRequest.php; app/Http/Controllers/Admin/HomeCardController.php; app/Http/Controllers/Admin/HomeContentController.php; app/Models/HomePage.php; routes/web.php; resources/views/admin/home/edit.blade.php; resources/views/admin/home/partials/{hero-form,card-section,card-form}.blade.php; resources/views/admin/partials/{photos,dropzone}.blade.php; resources/views/components/promo-card.blade.php; resources/views/home.blade.php; resources/js/{home-editor.js,card-sort.js}; tests/Feature/{HomeCardTest,AdminHomeContentTest,HomeTest}.php.
